2. Gemini key in Settings (BYOK)

Settings page:

Input for the API key (masked, show/hide toggle)
Test key button (a tiny Gemini call, shows valid or invalid)
Model selector (e.g. a fast/cheap model for topics, a stronger one for corrections)
Remove key button

Where to store it:

Option	Pros	Cons
A. Encrypted in MongoDB (recommended)	Syncs between phone and laptop	You trust your own server
B. Browser only (IndexedDB), sent per request in a header	Server never stores it	Re-enter on each device

For A, encrypt with AES-256-GCM using a server-side secret (ENCRYPTION_KEY in .env). Never return the full key to the frontend, only AIza...x9Fq.

How it works at runtime:

Request → auth middleware → load user → decrypt key
       → create GoogleGenAI({ apiKey }) per request → call Gemini

Create the client per request, never as a global singleton, so a key change in Settings applies immediately. If there is no key, the API returns 412 KEY_MISSING and the app redirects to Settings. Handle 429 (free quota hit) with a friendly "wait a minute" message and automatic retry with backoff.

3. Fully dynamic placement test

Generate one question at a time, adapted to your previous answers:

Start at B1 → Gemini generates question
→ you answer → backend records result
→ next prompt includes: current estimated level, topics already asked,
  last 3 results → Gemini generates the next question (harder/easier)
→ stop after ~15 questions or when the level estimate is stable
Question types: grammar, vocabulary, reading (Gemini writes the passage + questions), short writing, short speaking.
Each call uses responseSchema so the output is strict JSON: {type, level, question, options[], answerIndex, explanation}.
Pass "avoid these question themes: ..." in the prompt so there are no repeats.
Writing and speaking are graded by Gemini, returning {cefrLevel, grammar, vocabulary, fluency, feedback}.
Final result: weighted score mapped to A1-C2, plus strengths and weaknesses.
Every generated question is saved only as history (for your review page), never reused as a fixed bank.
4. Interests and dynamic topics

Interest picker (multi-select): the category list itself can be generated too. Seed a few big groups (Daily life, Culture, Sports, Travel, Work, Tech, World), then a "More fields" button asks Gemini to propose more, and "Add my own" lets you type any field. That gives effectively unlimited fields.

Topic generation:

POST /topics/generate { fields:[...], level, count:10, excludeTitles:[...] }
Prompt includes your level, fields, and the titles you already saw, so you always get new ones.
Add a random "angle" to each call (debate, storytelling, role-play, opinion, problem-solving) for variety.
Infinite scroll: reaching the end triggers another generation call.
"Surprise me" mixes your selected fields.
Each topic card: title, field, level, duration, 3 opening questions, 8 key words, and a role-play scenario (e.g. "You're at a football stadium ticket office").
Topics are stored in MongoDB per user, so you can favorite them and so excludeTitles works.
5. Live conversation

Flow per turn:

You speak/type → text → POST /chat/turn
→ Gemini returns JSON:
{
  "reply": "AI's next message",
  "correction": {
     "hasMistakes": true,
     "original": "I go to gym yesterday",
     "corrected": "I went to the gym yesterday",
     "explanation": "Past simple needed with 'yesterday'; 'the' before gym.",
     "mistakeType": "tense"
  },
  "newWords": [{ "word":"stadium","meaning":"..." }],
  "followUp": "question to keep you talking"
}
Stream the reply for a live feel, then parse the structured correction part.
System prompt sets: role, topic, your level (the AI adapts vocabulary and speed), "stay in conversation, correct gently, never lecture for long".
Settings toggles: correct after every message or only at the end, native language hint (French/Arabic) for explanations, strictness level.
Keep the last ~12 turns plus a running summary in context to save tokens.
Session end: Gemini generates a summary: score, top mistakes, new words, and a suggested next topic.

Chat UI:

Message bubbles with the correction shown as a card under your message (strikethrough original, corrected version in green, explanation).
Mic button (hold or tap to talk), live transcript while you speak, edit before sending.
Speaker icon on each AI message to replay it.
Tap any word to see definition, phonetics, and a "save word" button.
Slow/normal speed toggle, and hide-text mode for listening practice.
